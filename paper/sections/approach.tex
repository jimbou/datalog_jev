Figure~\ref{fig:pipeline} shows the approach.
For each app, the analysis builds the flow graph with every hole open.
For each clean, hole-dependent sink, it computes a receipt and its price, the bound.
A threshold certified on other apps decides which verdicts to clear.
This section defines each step and states what it guarantees.

\subsection{Receipts}
A \emph{receipt} for a clean, hole-dependent sink $t$ is a set $C\subseteq H$ of hole edges such that every path from a source to $t$ in $E_c\cup H$ uses an edge of $C$, that is, a cut.
\begin{lemma}\label{lem:cut}
If no edge of $C$ is in $T$, then no source reaches $t$ in $E_c\cup T$, so the verdict is not a miss.
\end{lemma}
\noindent Any path in $E_c\cup T$ is also a path in $E_c\cup H$ and would use an edge of $C$.
A receipt is therefore a list of library facts that, if all false, make the verdict correct.
Each fact names a method and two of its values (``the receiver of \texttt{CharBuffer.toString()} flows into its return value''), so a person or a test can check it.
Most receipts are short: of the leak-free sinks that our approach clears in the evaluation, 80\% rest on a single fact and 99\% on at most four.

\subsection{Prices and the Bound}
A \emph{pricer} gives each hole edge $h$ a price $p(h)\in[0,1]$, meant as the probability that $h$ is real.
By Lemma~\ref{lem:cut}, a verdict can be a miss only if some edge of its receipt is real, so by the union bound
\[\Pr[\text{miss}]\le\min\Bigl(1,\sum_{h\in C}p(h)\Bigr),\]
whatever the correlation between library flows.
A sink usually has many receipts, and we use the cheapest one: a minimum cut in the flow graph where hole edges have capacity $p(h)$ and code edges infinite capacity, computed by max-flow.
One might hope for a smaller bound by using the structure of the graph more cleverly.
The next result shows that this is impossible without information beyond the individual prices.
\begin{proposition}[Tightness]\label{prop:tight}
Among all joint distributions of $T$ with $\Pr[h\in T]=p(h)$ for every $h$, the largest probability that a source reaches $t$ in $E_c\cup T$ is $\min(1,\mathrm{mincut}_p(t))$.
\end{proposition}
\noindent\emph{Proof.}
For any cut $C$, reaching $t$ needs an edge of $C$, so the probability is at most $\sum_{h\in C}p(h)$, and hence at most the minimum over cuts.
Conversely, decompose a maximum flow of value $F\le 1$ into paths with flows $f_k$.
Let world $k$, with probability $f_k$, contain the hole edges of path $k$, and add further edges to the worlds until every edge $h$ has total probability $p(h)$; flow conservation leaves enough room for this.
Every marginal is then met, and $t$ is reachable with probability at least $F$, the min-cut value.\hfill$\square$

\noindent A tighter bound would need knowledge of how library flows depend on each other.
Probabilistic Datalog engines such as Praline~\cite{praline} can use such knowledge when it is available; with marginals only, their optimum on reachability is the min-cut.

\subsection{Certifying the Threshold}
A bound is only as good as the prices, and a language model's prices can be wrong.
We therefore do not compare the bound with $\alpha$ directly; we choose the threshold so that the definition of Section~\ref{sec:def} holds.
A verdict is accepted at threshold $\delta$ if its bound is at most $\delta$.
For a program $P$, let $L(P,\delta)=1$ if some verdict of $P$ accepted at $\delta$ is a miss, and $0$ otherwise.
Then $R(\delta)=\mathbb{E}_{P\sim\mathcal{D}}L(P,\delta)$ is the probability that a new program receives a wrong clearance, and it grows with $\delta$.

\begin{proposition}[Certified threshold]\label{prop:ltt}
Let $P_1,\dots,P_n$ and a new program be drawn independently from $\mathcal{D}$, and let $\delta_1<\dots<\delta_K$ be candidate thresholds.
For $k=1,2,\dots$, test the hypothesis $R(\delta_k)>\alpha$ with the exact binomial test of $\sum_i L(P_i,\delta_k)$ against $\mathrm{Bin}(n,\alpha)$ at level $\varepsilon$, and stop at the first hypothesis that is not rejected.
Let $\hat\delta$ be the last threshold whose hypothesis was rejected (accept nothing if the first is not rejected).
Then $\Pr[R(\hat\delta)\le\alpha]\ge 1-\varepsilon$, so $A_0$ with this rule is $(\alpha,\varepsilon)$-soundy.
\end{proposition}
\noindent This is fixed-sequence testing in the Learn-then-Test framework~\cite{lt}.
The losses $L(P_i,\delta_k)$ are independent Bernoulli variables with mean $R(\delta_k)$, each test is exact, and testing in a fixed order controls the probability of any false rejection at $\varepsilon$.
Two consequences matter for the rest of the paper.

\emph{The guarantee does not depend on the pricer.}
The proof uses nothing about how bounds are computed: a poor pricer, or a score other than the union bound, still yields a valid threshold.
What the pricer decides is how much is cleared.
In fact, only the order of the bounds matters:
\begin{proposition}[Only the order matters]\label{prop:order}
If $g$ is strictly increasing, running the procedure on scores $g(b)$ with thresholds $g(\delta_1)<\dots<g(\delta_K)$ accepts exactly the same verdicts as running it on $b$ with $\delta_1<\dots<\delta_K$.
\end{proposition}
\noindent Since $g(b)\le g(\delta)$ holds exactly when $b\le\delta$, every loss and every test is the same.
Rescaling prices therefore changes nothing; a better pricer helps only by ordering verdicts better, and only at the low end of the order, where clearing happens (Section~\ref{sec:rq4}).

\emph{The guarantee needs enough programs.}
\begin{corollary}[Calibration floor]\label{cor:n}
Even if no calibration program has a wrong clearance, the first hypothesis is rejected only if $(1-\alpha)^n\le\varepsilon$.
Hence no threshold can be certified for $\alpha<1-\varepsilon^{1/n}$, whatever the pricer.
\end{corollary}
\noindent With $\varepsilon=0.1$, certifying $\alpha=0.05$ needs at least 45 programs and $\alpha=0.02$ at least 114.

\subsection{Checking Facts}
\label{sec:verify}
A receipt names the facts a verdict rests on, and one fact often appears in many receipts.
When a person or a test can check a few facts, the receipts show which ones are worth checking.
We rank the facts that appear in the receipts of verdicts not yet cleared, using only the receipts and prices: by how many such verdicts contain the fact (\emph{count}), by that number weighted by the price (\emph{price}), or by how many verdicts a ``no'' alone would bring under the threshold (\emph{unlock}).
The top $K$ facts are checked.
A ``no'' removes the hole edge, which can make a sink unreachable even with all remaining holes open; a ``yes'' turns the hole edge into a code edge, so the analysis now reports the corresponding leaks.
Receipts are then recomputed and the threshold is certified again.
Because the ranking reads no answer and treats all programs alike, the procedure with checks is again a fixed rule applied to independent programs, and Proposition~\ref{prop:ltt} still holds.
