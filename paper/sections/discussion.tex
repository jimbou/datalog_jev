\section{Discussion}
\label{sec:discussion}

\paragraph{The guarantee is about library flows, not about the whole analysis.}
Receipts are meant to run on top of an analysis such as FlowDroid; our Datalog analysis stands in for it, with FlowDroid's models and source and sink list, because receipts need a stored flow graph with every hole open.
The stand-in is less precise than FlowDroid: on the 70 of 80 apps where FlowDroid gave an answer, our analysis reaches 58\% of the leaking sink methods FlowDroid reports, and only 1\% of the sinks it flags are also flagged by FlowDroid.
Restricting it to code reachable from entry points removed only 11.5\% of these sinks on the first 40 apps, so dead code is not the reason; the likely cause is that the analysis is context-insensitive and merges values from different calls of the same method.
The guarantee does not depend on this precision: it bounds how often a clean verdict is wrong because of library flows, for whatever analysis produces the flow graph.
RQ1 shows that receipts also work inside FlowDroid, where 43 of the 58 sinks that open holes add receive a receipt confirmed by FlowDroid itself.
Certifying a threshold for FlowDroid, however, needs more apps than we could analyze with it.
Our receipts need only a stored flow graph, built once with every hole open, so pricing and certifying them takes minutes.
Inside FlowDroid, a receipt needs repeated full runs: one with FlowDroid's models, one with every unmodeled method opened, and reruns that confirm each cut.
On 89 of 181 F-Droid apps that our analysis handles, these runs did not finish within 20 minutes and 10\,GB, and the apps we retried with 55 minutes and 24\,GB ran out of memory again, although FlowDroid's own analysis is unchanged.
% Update with the final count when bench/queues/fdr_retry_chain.sh logs FDRR-DONE (2026-10-09: 21 retried, none finished).
We therefore use FlowDroid to validate receipts and our analysis to certify them; a cheaper way to open holes inside a precise analysis is future work.

\paragraph{Other kinds of holes.}
Library flows are one kind of gap in a soundy analysis.
Receipts apply to any gap that can be written as a set of candidate edges.
As a test, we added edges for inter-component communication, from each Intent an app sends to each component that could receive it, with a key from explicit targets and manifest filters.
On 72 apps, 1{,}467 receipts contain such an edge, and the certified threshold clears 40.2\% of the hard slice at $\alpha=0.1$ with 1.4\% of apps wrong.
These edges reach no additional documented TaintBench leak, because most of its inter-component leaks pass through databases, files or static fields, which our analysis already connects.

\section{Threats to Validity}
\label{sec:threats}

\emph{Answer keys.}
No key is ground truth.
The main key contains language-model labels, K2 covers only part of the library, and the audit checks the facts behind accepted verdicts, not the rejected ones.
We address this with keys built in different ways (RQ3), with a key built from the answers on which two model families agree, which match a person's source checks on 95\% of the checked facts, and with random label noise.

\emph{Apps.}
The calibration apps are small open-source F-Droid apps; about half of the larger apps did not fit our memory limits.
Apps that bundle the same libraries are not independent, which we tested by keeping such apps together in each split (Table~\ref{tab:unit}).
The transfer to malware rests on 31 apps, which shows no sign of failure but is too few to estimate a risk near 5\% precisely.

\emph{Pricers.}
Jev is a commercial service, and hosted language models change over time; all prices are stored in our artifact.
For one panel model, 152 of 17{,}830 methods were priced through a different access path to the same model.

\emph{Checks.}
In RQ5 the answer key plays the person who checks facts, so the gains assume that checks agree with the key.

\emph{Definition of a flow.}
The results depend on what counts as a flow.
The definition is written down (Section~\ref{sec:flow}), the labels follow it with reason codes, and the one case where people commonly disagree, keeping a reference to an argument, does not change the certified clearance under either reading.
